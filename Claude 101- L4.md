Claude 101, Lesson 4: **How You'll Work with Claude on Your Desktop**

Course: Claude 101 (Claude Academy), lesson 4 of 13 Lesson length: 10 min (written lesson, no video)

Source: the lesson page. The "In simple words" lines and analogies marked "my own" are mine. Features can change, so the app may look different today.

**Learning goals**
Tell apart the three ways of working with Claude on desktop: **turn by turn**, **handing off whole tasks**, and **building software**.
Recognize which shape a task needs before I start.
Find where each way of working lives in the desktop app.

1. **The big idea**

The desktop app is Claude's "home base." All my work fits one of three shapes. The core skill of this lesson is spotting which shape I'm in.

Analogy (my own):

**Chat** = talking with a tutor, one question at a time.
**Cowork** = giving a job to an assistant and getting the finished work back.
**Code** = hiring a builder to work inside my project.

2. **Mode 1**: Working turn by turn (Chat)

In simple words: **a back-and-forth conversation**. I ask, Claude answers, I steer, Claude revises. The value is in the exchange.

Use it when:

The answer shapes my next question.
I want to stay involved on every turn.
The task is small, so a full setup would be extra work.

**Examples from the lesson:**

Screenshot an unfamiliar dashboard, ask what the metrics mean, then ask which ones matter.
Talk through a presentation by voice, get an outline, and revise section three (four turns).
Ask Claude to gather scattered product-launch notes, find unfinished items, and check connected tools for gaps.

Where it lives: Chat, which is the claude.ai experience plus native desktop features:

Feature                 	              What it does                            	               Note
**Quick entry**                      	Opens a small, always-on-top window     	          Double-tap the Option key on Mac
**Screenshots and window sharing**	  Claude sees what I see                  	                  Mac
**Dictation**	                         Speak instead of type                                 	   Mac
**Desktop connectors**	              Connect local tools and services	

3. Mode 2: **Handing work off (Cowork)**

In simple words: I describe the result I want. Claude plans, does the work, and returns it. I delegate instead of chatting.

**Use it when**:

The task has several steps in order.
The result must be saved as finished files on my computer. (A standalone deck or doc doesn't need a hand-off. On paid plans I can create those as artifacts; see the "Creating with artifacts" lesson.)
The work spans several tools.
It should run on a schedule or in the background.

**How I stay in control** (**oversight**):

Claude may ask scoping or format questions first.
It shows its plan, and I can watch progress and steer.
It pauses for approval on important actions (like sending email or sharing files) when set to ask first.

**Examples from the lesson**:

Look up pricing decisions across meeting notes, Slack, and email, then update the Q3 deck.
Turn a folder of 50+ documents (contracts, reports, transcripts) into a summary memo.
Set up a recurring Monday routine (messages, status update, meeting prep) as a scheduled task.

Where it lives: Cowork, which includes:

**Feature	                    In simple words**
**Local folder access**   	Claude reads a folder and saves finished work back into it. (Chat gives files as downloads instead.)
**Scheduled tasks**	         Run on my schedule. They run remotely, even if my computer is asleep or the app is closed. Tasks that need local files run locally, only while the app is open.
**Subagents**	               Parallel background helpers, each with its own context, producing one combined result
**Projects**	               Workspaces with their own files, instructions, and memory, built around tasks
**Browser use**	             With Claude in Chrome, Claude visits websites and pulls data (e.g. competitor prices from ten sites, or pages with no API)
**Computer use**	            When there's no connector, Claude can click, type, and open apps. It asks permission for each app and respects a blocklist. A research preview on Pro and Max
**Plugins**	                  Role-specific bundles of skills, connectors, and agents (e.g. sales, finance, legal). Find them under Customize > Plugins

4. Mode 3: **Building software** (Code tab)

In simple words: Claude works inside a codebase (a project's code): reading files, writing and changing code, and running commands.

Desktop features: visual diffs (side-by-side changes), a built-in terminal showing commands as they run, and git version tracking so I can roll back.

Where it runs (my choice):

Option	             What it means
**Local**         	Claude works on a folder on my computer, and can run a development server I preview in my browser
**Cloud**         	Claude works in a cloud environment linked to a GitHub repository. Sessions keep going if I close the app. Good for big rewrites or keeping work off my machine

(Cowork can also run in the cloud: beta, eligible plans. The lesson points to the "Introduction to Claude Cowork" course.)

Autonomy settings (how much freedom Claude gets):

**Manually approve**: Claude proposes each change and waits.
**Accept edits**: file edits are applied automatically.
**Plan**: Claude plans before changing anything.

Managing work: run several sessions across projects, and filter by Local/Cloud and status from the sidebar.

Note from the lesson: non-developers can skip this mode. The "Claude Code in Action" course covers it in depth.

5. **Summary table** (from the lesson)
I'm about to...	Shape	Where it lives
Ask, brainstorm, draft, or think something through turn by turn	Working turn by turn	Chat (quick entry, dictation, screenshots)
Hand off a multi-step task, a task across my tools, or a scheduled task	Handing work off	Cowork (folder access, connectors, scheduled tasks, subagents)
Write, test, run, and ship code	Building software	Code tab (Local or Cloud)

6. **Tips from the lesson**
I don't pick a tab first. I notice the kind of work in front of me, and the tab follows.
Before handing off, write down the outcome I want, not the first question I'd ask.
A hand-off doesn't mean stepping away: review the plan, watch progress, steer.
Cowork's approval gates keep me in control of what leaves my desk.

Key takeaway

**Identify the shape of the work first**:

Turn-by-turn thinking goes in Chat.
Multi-step deliverables and scheduled work go in Cowork.
Codebase work goes in the Code tab.

**Quick revision**
3 shapes: Chat (talk), Cowork (hand off), Code (build software).
Chat extras (Mac): quick entry (double-tap Option), screenshots, dictation. Plus desktop connectors.
Cowork extras: local folder access, scheduled tasks, subagents, projects, browser use, computer use, plugins.
Code: visual diffs, terminal, git rollback; Local or Cloud; autonomy: manually approve, accept edits, plan.
Oversight: Cowork shows its plan and asks approval before important actions.
Plans: Cowork and Code need Pro or higher; artifacts need a paid plan.

**Link to my goals**
Everyday use: most daily tasks will be Chat. Notice when a task is really a hand-off.
AI Security (later): this lesson is about how much freedom I give Claude (the Agency idea from AI Fluency). Approval gates, permission per app, blocklists, and "manually approve" settings are all security controls. Computer use and browser use raise the stakes, because Claude can act on real apps and websites.
